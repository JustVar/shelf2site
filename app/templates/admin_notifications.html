Slack Bot

{% if bot_configured %}

Bot token is active. Required scopes: users:read, users:read.email, chat:write, im:write

{% else %}

To enable Slack DMs, add SLACK_BOT_TOKEN=xoxb-... to the .env file on the server and restart the service.

# Add to /opt/asset_tracker/.env
SLACK_BOT_TOKEN=xoxb-your-token-here
# Optional: test channel for E2E runs
SLACK_TEST_WEBHOOK_URL=https://hooks.slack.com/services/...
How to get a bot token: Create a Slack App at api.slack.com → Install to Workspace → copy the Bot OAuth Token (starts with xoxb-).
{% endif %}

Email / SMTP

{% if smtp_configured %}

SMTP host is set. Users who enable Email delivery on their subscriptions will receive notifications at their account email address.

{% else %}

To enable email notifications, add SMTP settings to the .env file on the server and restart the service.

# Add to /opt/asset_tracker/.env
SMTP_HOST=smtp.office365.com
SMTP_PORT=587
SMTP_USER=notifications@example.com
SMTP_PASSWORD=your-app-password
SMTP_FROM=Asset Tracker <notifications@example.com>
# Set to false for SSL-only servers (port 465)
SMTP_TLS=true
Microsoft 365 / Exchange: Use an app password or service account with SMTP AUTH enabled. Contact your M365 admin if SMTP AUTH is disabled tenant-wide.
{% endif %}

How Notifications Work

1. User sets email
Each user adds their email via User Management. This is used for Slack auto-match and email delivery.
2. User subscribes
Click the bell icon on any provisioning detail page, or open the notification panel and go to My Subscriptions.
3. Choose delivery
Each subscription has independent Slack and Email toggles. Users can enable one or both channels per subscription.
4. Event fires
When a provisioning stage advances or completes, the app delivers to each subscriber via their chosen channels automatically.
Note: Slack DMs require SLACK_BOT_TOKEN. Email requires SMTP_HOST. Both channels are independent — configuring one does not affect the other. Notifications are suppressed during E2E test runs.
